fizh

On-device neural machine translation in Zig, compiled to wasm32-freestanding. This page runs SPEC §13 T5: the §14 budgets on whatever device you opened it with.

Invariant I1 says fizh exists because Mozilla's engine is intgemm-based and x86-tuned while phones are ARM. Testing that needs bergamot itself, on this phone, which is what the first table is.

1. Runtime

fizh ships one artifact. The +relaxed_simd variant and its probe module were removed: the artifact was byte-identical, and before that the feature made float code slower (ADR 0025).

2. Models

Fetched on demand: a pivot pair is ~40 MB and the wide architecture is 33 MB, so nothing downloads until you ask for it.

3. Results

I1 — three engines, one phone

The claim the project rests on. Cold start is part of it: bergamot instantiates ~5 MiB of engine, fizh ~104 KiB.

Distribution

A p99 is only reported where the run count supports one (300+). Below that the tail column says max and means it. Burst is the first quarter of samples, steady the second half — on a big.LITTLE phone those are different numbers and the gap is the scheduler.

Linear memory demanded is WebAssembly.Memory.buffer.byteLength at its maximum during the run, for both engines. It is not resident set size: growing commits pages but the OS need not keep them, and neither engine reserves up front.
